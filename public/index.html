Ledger

  1. 1

    The agent proposes

    You tell the agent what you need. It searches the live web and asks to buy specific products. It can only request a purchase: it cannot spend money and it cannot set a price.

  2. 2

    Policy checks

    Before PayPal is ever called, a rule engine checks the request against your mandate. A failed check blocks it and shows exactly which rule said no.

  3. 3

    You approve

    An allowed request becomes a PayPal order. You approve it yourself with the PayPal button under Approvals. Nothing is paid until you do.

  4. 4

    The server captures and audits

    After you approve, the server captures the payment, re-checks the amount, and records every step in the Ledger and the audit trail.

What the policy checks

  • Active The mandate has not expired.
  • Category The product's category is one you allowed.
  • Not a duplicate You are not already buying the same item.
  • Under cap The price is within the per-purchase cap.
  • Within budget Enough budget is left, counting orders still waiting for approval.
  • Pace The agent has not asked too often this hour.

Where prices come from

Search providers only suggest pages. The server opens each page itself and reads the price the retailer publishes. Anything it cannot verify is skipped, and a price older than six hours is refused as stale. The agent never supplies a price.

What the agent can and cannot do

Can

  • Search for products
  • Read your mandate
  • Request a purchase

Cannot

  • Spend or move money
  • Set or change a price
  • Approve its own orders

Payments run in the PayPal sandbox with test accounts, so no real money moves.
